# 그림 처리 세부와 스캔본 (4단계 보충)

SKILL.md 4단계의 판단 질문과 파일명 접두어 규칙은 항상 적용된다. 아래는 스캔본이거나, 그림을 페이지에서 잘라야 하거나, 벡터 도표를 다룰 때 읽는다.

## 스캔본(텍스트 레이어가 거의 없는 PDF)

**스캔본**(텍스트 레이어가 거의 없는 PDF)은 스크립트가 알아서 감지해 150dpi로 렌더링한다(`--dpi`를 직접 주면 그 값을 따른다). 이 경우 `text/`는 비어 있으므로 초안에 기댈 수 없고, 모든 페이지를 이미지에서 직접 읽어야 한다. 2단계의 분류 스크립트가 `SCAN-LIKE DOCUMENT`를 출력하면 이 상황이다.

## 그림 보존 세부 규칙

- **페이지 전체를 덮는 임베디드 이미지(스캔본)는 그림 후보가 아니라 페이지 자체다.** 스캔본에서 그림·사진·손글씨 도해를 보존해야 한다면 페이지 렌더에서 그 영역만 잘라 쓴다: `python3 scripts/crop_image.py <추출작업폴더>/pages/page_NNN.png <x0> <y0> <x1> <y1> <출력.png>` (좌표는 0~1 비율). 페이지 전체를 그림으로 붙이면 이미 텍스트로 옮긴 표·수식·문장이 이미지와 텍스트에 중복되므로 금지다. 작은 글자가 많은 그림·표·손글씨는 `python3 scripts/render_page.py <원본.pdf> <페이지> 300 <출력.png>`로 그 페이지만 높은 dpi로 다시 렌더링해서 확인하거나 자른다(이 스크립트 대신 임의의 명령을 쓰지 않는다). 그림 안의 라벨이 자른 경계에 걸리면 여백을 넉넉히(`--pad 0.03`) 잡는다. 벡터 도표도 마찬가지로 도표 영역만 자르는 것을 우선하고, 영역 경계가 불분명할 때만 페이지 전체를 쓴다.
- 벡터로 그려진 도표나 화살표 다이어그램은 `pdfimages`로는 못 뽑히는 경우가 많다 — 이럴 땐 (보존 대상으로 판단됐다면) 해당 페이지의 `render_file`(전체 페이지 이미지)을 압축해서 그림 참조로 쓴다.
- **판단이 애매하면 보존 쪽으로 기운다** (무손실 원칙의 안전마진). 사용자가 특정 자료를 지목해 "이건 사진도 남겨줘"라고 하면 그 지시가 항상 우선한다.
- 보존하기로 한 이미지가 하나도 없는 문서는 `images/` 폴더 자체를 만들지 않는다 — 그 문서의 결과물은 자연히 `.md` 파일 하나로 끝난다.

## 압축 후 파일명 규칙 (보충)

보존하기로 한 이미지는 그대로 복사하지 말고 압축부터 한다 (나중에 이 md를 다시 읽을 때 vision 토큰을 아끼기 위함). 이때 파일명 앞에 **문서 제목을 접두어로 붙인다** — 같은 과목 폴더 안에 여러 강의자료가 쌓이면 `images/`를 공유하게 되는데, 접두어가 없으면 서로 다른 문서의 `page_002_img1.png`끼리 파일명이 충돌한다:

```bash
python3 scripts/compress_image.py <추출작업폴더>/images/page_NNN_imgK.png <과목폴더>/images/<문서제목>__page_NNN_imgK.png --max-dim 1024
```

(`<문서제목>`은 이 문서의 최종 md 파일명에서 확장자를 뺀 것, 예: `01_실험기구의_사용`.) 압축된 파일만 최종 `images/` 폴더에 들어간다. alt 텍스트에는 원본 캡션이 있으면 그대로 쓰고, 없으면 이미지를 보고 직접 만든 설명을 붙이되 역시 1~2문장으로 간결하게 (검색 가능한 핵심 키워드 위주).
